Benchmarks

Protocol v1 is designed against measurements of what Occamy costs today, and it is proven with the same harness. Its two targets are a 10x improvement over the Guacamole baseline on each scenario's primary metric, and input-to-update latency under 50 ms for desktop interactions.

The harness and the stack share the host, so anything else that uses the CPU shows up in the numbers. Keep the host idle, and use -runs 3.

Running

make bench
make bench BENCH_FLAGS="-scenarios T1 -net N1 -series occamy"

This builds occamyd's image from the working tree, then builds and starts the demo stack with docker/docker-compose.bench.yaml on top, which publishes guacd on 127.0.0.1:4822. Results go to bench-results.json, and a Markdown table goes to standard output.

FlagDefaultMeaning
-scenariosallComma-separated scenario IDs
-netN0,N1,N2Network conditions
-seriesoccamy,guacdoccamy goes through occamyd; guacd connects directly
-runs1How many times to run everything; the table shows medians

What is measured

The harness is a client. It decodes every image into a framebuffer, answers each sync once the frame is applied, and sends a nop every 5 seconds, as the web client does. Each scenario runs on a fresh session. Bytes are the TCP payload through the proxy, and server CPU is the CPU time of the occamyd and guacd containers during the measured part of a scenario.

A proxy inside the harness carries every connection. It adds half the RTT in each direction and serializes at the bandwidth, with a queue of twice the bandwidth-delay product. It does not emulate loss. See the spec for the scenarios and how the targets are judged.
